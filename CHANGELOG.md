# Changelog

## Unreleased

- Fixed: **text on the pop-up screens is no longer squashed to fit.** The Kernel Panic, Build Successful, briefing and summary boxes were a fixed width, and any line too long for one was squeezed narrower rather than given more room — so the death screen that offers you a rollback, whose lines are the longest in the game, rendered them noticeably compressed against the edges of the box. The boxes now grow to whatever their text actually needs, up to the width of the window. Screens whose text already fitted look exactly as they did

- New: **the death screen now has an opinion about cheating.** The HUD has always stamped a warning on a run once you use one of the cheat codes, so you know the score will not be recorded — but the Kernel Panic screen itself said exactly the same thing to a cheating player as to anyone else. Die with a cheat behind you and it now has one extra line for you. You will have to earn it. The screen is untouched for everyone else, the line stays out of the way when the death is one you can roll back from, and nothing about how the game plays or scores has changed

- Fixed: **the tab marker no longer says "paused" when there is nothing to resume.** The small **▶**/**❚❚** beside a tab told you whether the level was running — except it appeared the moment you picked a workspace and then never left, so a finished run, a campaign you had completed, or a repository that failed to load all sat there showing **❚❚**, as though a level were paused and waiting. The mark now exists only while a level does: it appears when one loads and disappears when the run ends, the load fails, or you have not started yet. Two related lies went with it — the mark used to read **▶** for the whole Kernel Panic and Build Successful screen, insisting the level was still running while you looked at the results, and a co-op session left the tab you launched from stuck on whatever it last showed

- Changed: **the guided tour covers two things it used to skip.** The **Repo** tab now gets its own step — that it takes GitHub, GitLab *and* Codeberg addresses, that a bare `owner/repo` still means GitHub, that only public repositories work, and that there are four suggestions from Easy to Nightmare if you would rather not choose one. And the highscore step now says what the board actually holds: which difficulty a run was played on, how many rollbacks it spent, and the difference between **Watch** (replays the run) and **Export** (records that playback to a video file, in real time, with the controls locked until it finishes). It also stops promising that every entry can be replayed, which was never quite true — a run recorded before a balance change reads "rules changed" instead

- New: **dying is no longer always the end of the run.** Until now, running out of System Stability ended everything: Kernel Panic, back to the file tree, and a campaign fourteen levels deep was simply gone. A run now carries a small budget of **rollbacks** — **2 on Easy, 1 on Normal, and none on Hard** — and the death screen offers you one. **Roll back** puts you at the start of the level you died on with the health, armour, ammunition, weapons and score you *walked in with*; everything the failed attempt earned or spent goes with it, and so does the damage you took. **Give up** ends the run as before. Roll back is the default button on purpose: Space is also the fire key, and a trigger pulled in the fight that just killed you should not be able to end your run by accident — Escape gives up, and on a pad it is A and B. The number you have left sits above the status bar while you play, and disappears once you have spent them. **Hard gets none deliberately**: it is the one difficulty where dying still ends the run outright, the Kernel Panic screen keeps its single button, and the badge never appears at all — a tier whose whole point is a tighter margin should not also hand the run back. **The level is the same but the fight is not**: the layout is built from your source file and never changes, so everything you learned about where the rooms and the exit are still holds, while enemy timing, aim, what they drop and how your shots spread are all rolled fresh — a rollback is another attempt, not a rehearsed one. A continued run **still posts a score**; the Highscores dialog marks it in a new **RB** column, so it is told apart from a clean run rather than thrown away, and watching its replay shows the run you actually finished rather than replaying the attempt you abandoned. One detail worth knowing: a rollback is spent the moment you die, not when you press the button, so closing the tab at the Kernel Panic screen is not a way to get a free one. Rollbacks are single-player only — a co-op session still ends when the whole team is down. **No replay recorded before this is affected**, and the bundled highscore board did not need regenerating: nothing about how the game actually plays has changed

- Changed: **the difficulty setting locks once a run is under way.** It used to be changeable at any moment, taking effect from the next level — which meant you could clear fifteen levels on Easy, switch to Hard for the last one, and post a Hard-labelled score. Your score does not scale with difficulty, so the tier is the only thing telling an easy 8,000 apart from a hard one, and the board had just started recording it. Pick your difficulty before you start; it opens up again the moment the run ends, and the setting itself is still remembered between sessions. **Gore and render quality are unchanged** and stay switchable whenever you like — neither affects how the game plays or what you score

- New: **the highscore board says which difficulty each run was played on.** It never used to, which was tolerable while every row was a run with one life — and stopped being tolerable the moment rollbacks arrived, because an Easy run that restarted two levels could sit above a clean Hard run with nothing on the table hinting at the difference. There is now a **Difficulty** column beside the **RB** one, and the two are only useful together. **Runs recorded before this still show their real difficulty** rather than a dash: every replay already stored the difficulty of each level it recorded, so the board reads it back from there — including the built-in board you see before you have set any scores of your own. The one case it declines to answer is a run whose difficulty was changed partway through, which has no honest single label; that shows a dash, and the replay still has the level-by-level truth

- Fixed: **the Kernel Panic screen no longer says you have no rollbacks while offering you one.** On your last rollback it read "0 rollbacks left" directly above a live **Roll back** button, which reads as a bug even though the number was technically right — a rollback is counted the moment you die, so the figure was what you would have left *afterwards*. The screen now describes the choice in front of you instead: "this is your last rollback", or how many follow this one

- Fixed: **closing the tab on the death screen no longer leaves you a saved run that dies instantly.** If you died and closed the tab without clicking anything, the game wrote your progress one last time on the way out — using the moment you died, at zero health. The result was a **Continue Run** button that looked completely normal, re-picked your folder, rebuilt the level, and then killed you in the first fraction of a second, every time, with no way to tell why. It now saves the start of the level you died on instead (with the rollback already counted, so it is not a free retry), and a run that genuinely ended saves nothing at all

- Added: **keys ping when you walk past them, not just when a door turns you away.** The minimap ping already existed, but only ever fired *after* you had walked into a locked door with no key — which is the moment it is least useful, because by then you have already gone past wherever the key was. Now passing a room that still holds a key you can actually reach sets off the same marker and sonar ring on its own. There is no thunk and no banner, because nothing refused you; it is just the game making sure you saw the thing. It fires **once per key per level** — the point is that you noticed it, not to keep nagging about a detour you already decided against — and a key lying loose in a corridor rather than in a room pings too, once you are within a few tiles of it. Walking into a locked door still behaves exactly as before, and still wins if both would fire at once

- Changed: **the Toolchain chainsaw runs instead of stuttering.** Holding Space used to fire a swing every 0.35 seconds and, in between them, quietly put the chainsaw away — the weapon on screen flicked back to whatever gun you had equipped for the last few frames of every single cycle, and the sound cut out for about a fifth of a second between each buzz. Both of those were the same mistake: something you *hold* was built as a thing that happens repeatedly, with a gap in the middle. Now the chainsaw stays in your hands the entire time the key is down, kicking as it bites and settling between bites, and it has a real two-stroke motor behind it — mostly the rattle of the chain in the bar, over an engine that idles, bogs down when it chews through something, and spins down when you let go. **The damage is completely unchanged** — same 0.35s bite, same 80 a hit, same heal per kill. It just finally behaves like a tool that is switched on

- Changed: **a proximity mine no longer looks like a red keycard.** Both were drawn the same way — a dark red square with a brighter red square inside it — which meant the one object in the game that takes 32 health off you was wearing the exact uniform every pickup wears, in a red barely distinguishable from the red key's. The predictable thing happened: players learned to flinch away from red keycards. A mine is now a domed device sitting on the floor, with three prongs and a single glowing lens, and a keycard is still a flat square floating at waist height. **The difference is the shape, deliberately, not the colour** — a mine stays red and still breathes, because both of those are what make it noticeable in the first place, and shape is the cue that still works at a distance and if you are red-green colour blind. The docs never actually said what a mine looks like in the world; there is now a picture of the two side by side

- Changed: **gdb hits harder — it is no longer a worse pistol you unlock later.** The last round of changes made the enemies tougher and promised your weapons were untouched. That was the right call for the pistol and the shotgun, and it quietly left one gun stranded: gdb, the full-auto weapon you don't get until campaign level 4, was doing **12 damage a round against the starting pistol's 22**. Fire rate is supposed to make up the difference, and it didn't — 11 rounds a second against the pistol's 6.6 worked out to *less* damage per second than the gun you begin the game holding, out of a weapon that also has the longest reload of the three and burns four times the ammunition to get there. There was no situation where picking it up was an upgrade, only a trade for a trigger you could hold down. It now does **16 a round**, which puts it about a fifth ahead of the pistol per second and comfortably behind the Regex Shotgun's point-blank blast, so each of the three has something the other two don't: the shotgun ends a fight in one pull if you're close enough, gdb wins the long exchanges, the pistol wastes the least ammunition. Against the small cyan Edge Cases that fill the corridors it's the difference you'll feel first — most of them now take two rounds instead of three, though the toughest still need the third. **The ammunition economy is unchanged on purpose**: SMG ammo still arrives in 21-round bursts and is still the least efficient in the game per round, because that is what the rate of fire is paid for. **This invalidates every replay recorded before it**; the bundled highscore board was regenerated

- Changed: **enemies are meaningfully tougher, and almost nothing dies to a single shot any more.** Two numbers were wrong in the same direction and it took a playtest to see it. A full shotgun blast does 175 damage, and 99 out of 100 enemies in the game had less health than that — so the shotgun one-shot essentially everything, on every difficulty, and there was never a reason to fire it twice. Meanwhile the small cyan Edge Cases that fill the corridors are **more than half of every enemy you meet**, and at 10-15 health a single pistol round killed 999 of every 1,000 of them. That is why the pistol felt strong: it wasn't, but most of what you were shooting at was free. Both are fixed at the source rather than by nerfing your guns — a function's enemies now carry **35 health per point of complexity instead of 25**, and an Edge Case has **25-35 instead of 10-15**. A regular enemy now takes five pistol rounds instead of four, an Edge Case takes two instead of one, and the toughest fifth of enemies survive a shotgun blast and shoot back. Your weapons are untouched — the guns were never the problem, and the ammo economy had enormous slack to absorb this: even the tightest levels still hand you several times the ammunition their enemies are worth. **Easy is deliberately left as it was**: its health reduction keeps Edge Cases inside one pistol round, which on Easy reads as intended rather than as the bug it was on Normal

- Changed: **healing now depends on what you killed.** Every kill has always topped your health up when you were hurt, by a flat amount — which meant that clearing a corridor full of the small cyan Edge Cases kept you permanently full, for free, because a 30-health nuisance handed back the same 20 points as a real enemy did. The top-up is still guaranteed, and still there for exactly the reason it always was: running out of health is the one thing that actually ends a run. What changed is the size — it's now proportional to the health of whatever you just killed, so trash gives back a trickle and something that genuinely fought you gives back a real chunk. In practice you'll notice it as a health bar that reflects how the level has gone rather than one that refills itself on its own

- Changed: **ammo drops now depend on what you killed, so a level pays for itself.** A kill has always dropped a fixed amount of ammunition regardless of what died — which meant a level built from a handful of large, complex functions handed you far too little for the fight it put in front of you, while a level of many small ones buried you in ammo you'd never spend. Loot was counted per body; the cost was paid per bullet. A drop is now proportional to the health of the enemy that dropped it, so the tough ones pay out properly and the trash pays out a trickle. **The total amount of ammunition in the game is unchanged** — it moved from the levels that were drowning in it to the levels that were starved. In practice: the levels that used to leave you scraping are the ones you'll notice, and everything in the middle plays exactly as it did

- Changed: **a long campaign no longer trivialises itself.** Ammunition carried between levels was never bounded, so on a large repository you arrived at level 60 holding everything you hadn't spent since level 1 — against opposition that doesn't grow with your reserve. Deep into a big codebase the game had quietly stopped being a game: measured across 23 real repositories, a late level handed you nearly **eighteen times** the surplus an early one did. What you carry in is now capped against what that level would give a fresh player, so a full reserve is still a full reserve — it just can't compound forever. **Early levels are completely unaffected** (there's nothing to cap on level 1, and the first few never come close to the ceiling), and no level anywhere became unclearable. What changes is the late game: picking things up matters again, where before it hadn't for hours

- Fixed: **the status bar no longer draws a long number over its neighbour.** Once your bullet reserve reached four digits, the AMMO readout ran off the left edge of the bar and the first digit was cut off by the screen — and the same was quietly true of **SCORE**, which had room for four digits while a finished campaign routinely scores five or six, and of the ammo table on the right, where a five-figure pool was drawn straight through its own `BULL`/`SMG` label. Every readout is now sized to the space its panel actually has: it keeps the full-size digits whenever they fit — which is every reading on a normal bar, so nothing you are used to looks any different — and steps down a notch only for the value that would otherwise spill out. The ammo readout also drops the spaces around its slash, so `9 / 31` reads `9/31` and buys back two digits' worth of room

- Fixed: **the violet key no longer hangs out of the KEYS panel.** On a level with all four locked rooms, the fourth pip was drawn past the edge of its own section of the status bar and sat inside SCORE — visible at the default render setting, though not at Sharp, where the bar is wide enough to hide it. The pips are laid out **two across and two down** now, so four of them take the same width as two and the panel can always hold whatever a level throws at it. A level with one or two keys looks exactly as it did — the block grows upward, so the row you are used to stays where it was and a third key adds one above it

- Fixed: **a locked door is never a dead end any more.** Walking into a door you have no key for names the colour you're missing and pings that key on the minimap — except the key you need is usually sitting inside a room that *another* key opens, and in that case the game used to ping nothing at all. You got a colour and silence, with no way to work out where to go. Measured across a corpus of real repositories, that was **71% of the doors you walk into**, so it was the normal case rather than a corner of it. Now, when the key you asked for is out of reach, the banner adds a second line naming the key that unblocks it — *"find the green key first"* — and the minimap pings **that** one instead, in its own colour. Whatever door you bump into, there is always somewhere to go next. Two smaller things came with it: a door you already hold the key for no longer counts as an obstacle when the game works out what to point at, and the key it names is one the door you asked about genuinely depends on, not merely the closest

## beta-8

- New: **load repositories from GitLab and Codeberg, not just GitHub.** The GitHub tab is now a **Repo** tab that takes a repository URL from any of the three — paste it and the host is worked out from the address, with the button naming the one it recognised ("Load from GitLab") so you can see it got the right one before the download starts. A bare `owner/repo` with no host still means GitHub, so nothing you already type changes meaning, and a saved run remembers which site it came from and resumes against that one. Very large GitLab and Codeberg repos come back a page at a time and stop after 40 pages rather than exhausting what those sites allow an anonymous visitor in an hour; when that happens the same "partial listing" marker appears above the file tree as for an over-large GitHub repo
- New: **the status bar is a proper DOOM-style bezel.** It now runs `AMMO · STABIL · TOOLS · your face · SWAP · KEYS · SCORE` with a full ammo table on the right, instead of a handful of readouts clustered at the left edge. **TOOLS** shows which dev tools you are carrying at a glance — one cell per number key, dim if you have not found it, boxed if you own it, filled for whatever is in your hands, melee is not shown there, since it has no number key — the AMMO panel reads MELEE whenever it is in your hands. **The ammo table** lists every pool at once (`BULL`/`SHEL`/`SMG`/`RCKT`/`GAS`) with the one you are spending lit up, so you no longer have to cycle weapons to find out whether you have rockets. And **the face** is you: it gets visibly beaten up as your System Stability drops — cuts, bruising and blood that stay on it rather than appearing only for a moment when you are hit — and when something hits you it turns toward whatever hit you — so a bite from off-screen tells you which way to look. Traps and acid have no direction and just hurt. The bar scales to the window rather than sitting on fixed positions, so it fills the width at the Sharp render setting too

- New: **rooms with real code in them are busier, and a private method now has a proper gatekeeper.** Enemy count has always scaled with how complex a function is — except it barely did: the threshold was set so high that on real code, 19 rooms in 20 held a single enemy no matter what was in them. It now takes effect where you would expect, so a branchy function is a fight and a one-line getter still is not. Separately, a **private or protected** method — the kind that becomes a key-locked room — now puts a noticeably tougher enemy at the front of its pack with lighter escorts behind, instead of a row of identical bodies. The room's total strength is unchanged, so it is a different shape of fight rather than a harder one: kill the gatekeeper first and you will take more damage than if you clear the escorts and leave it for last. A handful of `switch`-heavy rooms also mix a fast, fragile Edge Case in among the regulars

- New: **enemies no longer all shoot the same thing, and you can tell which is coming by its colour.** Every enemy in the game used to fire an identical magenta bolt — an Elite's shot and an Edge Case's were the same attack, just with the number behind it turned up or down. Now each has its own. An **Elite** fires a slow orange shell, rarely, that hits far harder than anything else in the game and is slow enough to actually step out of the way of — so an Elite at range is a threat you *react* to rather than one you just absorb. An **Edge Case** sprays fast, weak, slightly-off-target cyan bolts about twice as often, which chip at you while you are busy with something bigger. A regular enemy's magenta bolt is unchanged. Each type still deals about the same damage over time as it always did: what changed is how it arrives, not how much of it there is
- Fixed: **a rocket can no longer fly straight through an enemy.** ghidra's rocket moved in a single jump each frame and only asked what it had hit once it landed — so on a slow frame it could step clean over a target it should have hit. At the longest frame the game allows, roughly one target position in nine was simply unhittable, every one of which lands normally at a healthy frame rate. It now checks the whole path it travelled rather than only where it ended up, so whether a rocket connects no longer depends on how the frame went. Its damage and blast radius are untouched

- New: **the player guide explains what every colour means.** A new [Colours & Pickups](doc/user/colors-and-pickups.md) page: a full legend for the corner minimap, the automap and an exported map PNG, and — for the first time written down anywhere — what a dropped item actually looks like. Every pickup in the game is the same small two-square shape, so colour is the *only* thing telling health from swap from ammo, and that was left for you to work out. It also covers the two that reliably catch people: acid reads orange on both maps but green in the world, and an uncollected key shows up gold whichever key it is
- Fixed: **keys on the ground now actually show their own colour.** Colour-coded locked doors shipped in beta-7, and every part of it worked except the one you look at most: the keycard lying in the room. It drew blue whatever door it opened, so on a level with a red or green room the key you were walking toward was telling you the wrong thing, while the door, both map dots, the HUD pip and the "You need the *green* key!" message all had it right. Red, blue, green and violet keys now each look like themselves. Nothing else about keys changed — they still open every door of their room, and are still never spent
- Fixed: **a gamepad can now interact and sprint.** Two actions had no button at all: you could not read a lore terminal or open a fake wall — which meant **secret rooms were unreachable on a pad** — and you could not sprint. **A** interacts, and clicking the **left stick (L3)** sprints for as long as you hold it. Everything else is unchanged, and keyboard and pad still work at the same time

- New: **two more gore levels — Excessive and Absurd.** Extreme is no longer the top of the dial. **Excessive** roughly doubles Extreme: twice as much blood on screen at once, lingering about a third longer. **Absurd** is a different thing rather than more of the same — blood that has landed never dries up, so a room you fought your way through is still painted red when you walk back into it, and the splats are big enough that a floor you have been fighting on goes solid red rather than speckled. It has a ceiling (the oldest blood makes way once there is enough of it), but it is comfortably the most expensive setting in the game, so drop a tier if things feel choppy. Neither one makes blood bigger *up close*: point-blank splats are capped exactly as before

- Fixed: **the file tree now belongs to the tab you loaded it from.** Launching the Demos campaign used to leave its files listed under the GitHub tab too — there was only ever one tree, so whatever you loaded last showed up everywhere, under every tab. Now the files sit under the tab that loaded them, the other tabs say what they'd load instead, and Settings and Multiplayer stop showing you a workspace they have nothing to do with. A small **▶** marks the tab the game is running from — turning to **❚❚** whenever it isn't, whether that's a pause, a lore terminal, an undismissed briefing or the file tree between levels — and switching tabs only changes what you're looking at: it never disturbs the level you're playing, and the folders you expanded stay expanded. A repository that fails to load also reports it under GitHub now, instead of relabelling the campaign you were in the middle of
- New: **All settings now live in a dedicated Settings tab.** The gear (⚙) tab in the sidebar collects the Gameplay, Audio and Texture Pack controls that used to sit above the file tree — so the sidebar shows more of your files, everything is still remembered between sessions, and the guided tour now steps through the tab and returns you to where you were
- New: **Render quality — Classic vs Sharp.** Classic keeps the intended 640×400 retro look and stays the default; Sharp renders internally at 1280×800 — crisper walls, sprites and weapon — paired with a half-resolution floor so it stays fast, and is worth trying on a 120Hz display. Applies at the next level you launch, and aiming and shots behave identically in both modes
- Changed: **the floor costs about half a millisecond a frame less to draw**, and nearer a millisecond and a half of that at the Sharp setting — the renderer now writes each floor pixel in one go instead of one colour channel at a time. Nothing looks any different; it is headroom, and it is a good part of what makes Sharp affordable on a fast display

- New: **the game remembers your texture pack.** Pick one from the Online list and it comes back on its own next time, instead of resetting to the built-in look on every reload. A new **Use built-in textures** button reverts whenever you want, and forgets the choice. Two deliberate limits: a *local* `.wad` file still can't be remembered — a browser gives a page no durable handle to one — so choosing a file also clears a remembered online pack rather than letting it override your choice on the next load; and if the pack can't be fetched (offline, usually), the built-in textures stay up for that session and your choice is kept

- New: **weapons reload.** Every gun but the flamethrower now holds a magazine — 9 rounds for the echo pistol, **2 shells** for the Regex Shotgun, 45 for gdb, a single rocket for ghidra — and empties into a reload instead of firing forever from one undifferentiated pile of ammo. Fire it dry and it reloads itself; press **R** to top it up early, before a fight rather than during one. The HUD shows what is loaded against what is left in reserve, and a reload only ever *moves* ammo, so nothing is lost by reloading a half-empty gun. Switching weapons cancels a reload, so you can always swap to something loaded instead of waiting — and quick-melee still works throughout, which is exactly what it is for. It changes how the arsenal feels most at the extremes: the shotgun's two barrels are now a real decision, and ghidra reloads after every rocket. You can see and hear it too: the weapon swings well clear of centre and back, and each gun has its own sound — three light clicks for the pistol, shells shoved into the tube and the pump racked for the shotgun, a heavier five-part cycle for gdb, ghidra's breech swinging open and latching shut. On a gamepad it is **X**. There is deliberately no toast for it: ghidra reloads after every rocket and the shotgun every two shells, so one would be firing more or less permanently
- Changed: **`R` reloads, so interact moved to `F` and fullscreen to `Alt`+`Enter`.** Three bindings shuffled to make room for the genre-standard reload key. `F` now reads lore terminals and opens fake walls

- Changed: **the shotgun has its own ammo.** It used to spend 4 bullets a shot out of the same pool the pistol draws from, so your two starting weapons were rivals from the first minute of every run — every shell you fired was four pistol shots you no longer had, and the shotgun quietly punished you for using it. It now takes one **shell** from its own reserve, and shells drop, restock in Vendor Depots and count toward your end-of-level ammo bonus like every other pool. The shotgun's damage and its pump cadence are untouched: what changed is what a shot *costs*, not what it does

- New: **a boss key.** `F9` drops a plain code editor over the whole page — showing the actual source file the level you are playing was generated from, syntax-highlighted — and takes everything else with it: the game pauses, fullscreen is dropped, the music stops, and the browser tab's title and icon become the file's. Press `F9` again and it all comes back, revealing the game **still paused**, so you are not dropped straight back into a fight; your next click resumes as usual. `Escape` is ignored while it is up, so a reflex press can't undo it. Two honest limits: a web page cannot minimise its own window, which is why the disguise happens inside the page; and in co-op it can only hide you, not pause the session — the same as alt-tabbing out of co-op already does


## beta-7

- New: **a guided tour the first time you open the game.** Seven popouts over the launch screen point at the controls that actually start something — the launch tabs, Demos as the zero-setup path, co-op, difficulty and gore, the file tree, the highscore board and the console. Skippable, Escape closes it, arrows move between steps, and it never appears again once dismissed. There was a static intro screen and a link to the written guide before, and neither pointed at anything you could click
- New: **locked doors are colour-coded, and so is everything that points at them.** The door in the world, its dot on the minimap and automap, the key sprite, the "You need the blue key!" message and a row of key pips on the HUD all share one colour per room — so you can see from across a room which door your key fits, and a door you cannot open yet becomes a landmark telling you where to come back to. Deliberately no yellow: amber already means a switchboard door you can just push
- New: **you can name yourself.** A "Player name" setting, remembered between sessions, that labels your runs on the leaderboard — which now has a Player column — and, in multiplayer, floats above your character in the 3D view in your own marker colour (the same colour your dot already has on the automap and minimap). It also replaces "Host"/"Guest-1" on the end-of-run comparison table. Leave it blank and everything reads as it did before
- Changed: **an Elite is a fight you can lose, not one you cannot win.** A very complex function used to become one enormous enemy — up to 50,400 health from real code — which in practice meant a wall you walked past rather than a boss you fought: across seven repositories of automated playtesting, 1,332 Elites spawned and 2 died, none of them on Hard, and every single cleared run left the Elite alive. The room now keeps its doubled health budget but splits it across a pack led by a gold-tinted Elite, so nothing in it outlasts what you can actually chew through and the incoming damage drops as you cut the pack down. The largest enemy the generator can produce fell from 50,400 to 525. Levels that had never been beaten now are: one wolf3d level went from 0 of 78 attempts to 40 of 44
- Changed: **the flamethrower thins out with distance instead of stopping dead.** Friday Hotfix had a hard 3.5-tile reach — full damage at 3.4 tiles and literally nothing at 3.6. It now does full damage to 2.5 tiles and fades to nothing by 6.5, which is a redistribution rather than a buff: the plateau ends *before* the old cutoff, paying for the extra reach. It was locked to the wrong band entirely — ordinary enemies are fought at a median 4.6 tiles, outside its old range, while only the 10-15 health nuisances sit inside it
- Changed: **a key opens its room, not one doorway.** A locked room with six ways in used to cost six keys, and coming back through a door you had already opened charged you again. Now every locked room has one coloured key that opens all of its doors, and keeps working — the genre's own idiom, and the thing this game was already dressed as. Measured on the bundled campaign: `stage06` went from five keys to two for the same two rooms
- Changed: the three runs on the shipped leaderboard now say which bot set them — **Casual**, **Gamer** and **Pro**, the playtest bot's own skill profiles. They were three anonymous rows before, with nothing to say why the scores differ
- Changed: a `TODO` comment's encounter — a trap, a mine, or a "Bug" enemy — now follows the wording of that comment, so the same TODO always produces the same thing instead of being re-rolled whenever something unrelated shifts elsewhere in the level

## beta-6

- Changed: **levels are laid out completely differently.** Rooms are placed next to each other instead of scattered and joined up in source order, so a level is a connected complex rather than rooms strung along enormous hallways. The walk from one room to the next fell from 59 tiles on average (191 at worst) to 22 (48 at worst), and a level fills over a third of its own footprint instead of a fifth
- Changed: corridors don't all look the same any more. A corridor now has a width — most a single-file squeeze, some two- or three-tile halls — long ones can step diagonally, and the shapes that interrupt them went from two to six, never the same twice in a row: 84 across the campaign instead of 277 all-but-identical ones
- Changed: levels have loops. Rooms that land near each other get an extra connecting corridor, so there's usually more than one way round instead of a single branching dead-end tree. A shortcut never opens a new way into a locked room, so it can't cost you an extra key hunt
- New: levels no longer all look alike. Each picks one of five visual stylesets — warm stone brick, rusted metal, grey tech panelling, pale marble blockwork, or the cool teal bonus levels already had — and keeps it for the whole level. Which one it gets comes from the source file, so a given file always looks the same; hazards keep their colours everywhere, and teal stays reserved for `.h` bonus levels
- Changed: a loaded WAD texture pack now skins all five stylesets separately, so real Doom textures give you the same level-to-level variety the built-in look does. A sparse pack borrows between stylesets before falling back to the built-in art, and the status line reports what each got
- New: a `switch` (or `match`) statement builds a **Switchboard** — that function's room becomes a junction with a short dead-end spur per `case`, each behind an amber push-open door and holding something small: a weak enemy, a trap, or ammo. The `default` branch gets no spur, because it's the way onward
- New: a `try`/`catch`/`finally` becomes a three-part detour — a narrow acid corridor with spike traps and a mine, an alcove of guaranteed health *and* armor at the far end, then a safe room with guaranteed loot. The acid corrodes away a couple of seconds after you step in it, so the walk back out of the dead end is free, and no dependency key ever spawns past a gauntlet — the toll stays a bet you choose to take
- New: the imports (or `#include`s, or `require`s) at the top of a file become small **Vendor Depot** alcoves in the wall of the room you start in — roughly one per four imports, stocked with ammo for the weapons you're actually holding, including the ones levels 4, 8 and 12 grant you. SMG and gas ammo can turn up there too, not only as enemy drops
- New: a function that allocates memory heavily gets a room that **leaks**. Walk in and the floor fills with acid tile by tile until you kill the enemy that function spawned, then it stops right where it is. A low warning tone and a "Memory leak — acid rising!" banner fire the moment it starts
- New: there are now two kinds of door. The blue one still needs a dependency key; the new amber one is a Switchboard's branch door and just needs a push. Both have their own colour on the minimap and automap
- Changed: a locked door tells you why it didn't open. It thumps, a "You need a key!" banner appears, and the nearest key you can actually reach pings on the minimap for a few seconds — picked by walking distance, so it never points you at one sitting behind another locked door. If every remaining key is walled off, you get the thump and the banner with nothing to follow
- Changed: every gun has its own cadence now, and none of them can be out-clicked. The Regex Shotgun is pump-action again — 0.85s between blasts, with an audible rack — and its pellets hit harder to match (18 → 25 damage each); the echo pistol caps at ~6.6 shots/sec. The cap is per player, so switching guns mid-cycle doesn't help; quick-melee on `Space` is always available
- Changed: Elite enemies are half as tough. Crossing the complexity threshold used to quadruple a room's health and put it all in one body that also hit twice as hard — one extra point took a room from four enemies with 976 health between them to a single enemy with 4000. An Elite is still clearly the harder fight, just not an unkillable wall
- Changed: monsters no longer spawn right on top of the exit marker. Enemies aren't solid, so this is about how the way out reads, not whether you can use it — what holds the exit shut is unchanged: every enemy belonging to its room has to be dead
- Fixed: the game now holds a steady 60fps where it used to sit around 44-51 and judder. Roughly one frame in three arrived late, because of *how* a handful of outlined and curved shapes were drawn — the weapon silhouette, the minimap arrow, tracers, blasts, flame jets — which are now stamped from pre-rendered images or built out of rectangles. Standing still 51.3 → 58.6fps, fighting 48.8 → **59.1**, automap open 44.3 → **59.0**, late frames down from 17-36% to under 2%
- Fixed: replays of long runs are no longer cut short. A level running past the recording limit stopped being recorded and the replay closed the gap as if it had never happened, so a full seventeen-level clear shipped as a two-level replay. The limit is now twelve minutes, up from six, and a replay that does hit it stops there instead of pretending to be complete
- Fixed: a saved replay is refused if the game's balance changed since it was recorded, instead of quietly playing a run that no longer matches its own score. The old check only covered the level's source file, but enemy health, the weapon table and constants like acid decay are generated from it rather than stored. **This invalidates every replay recorded before it**; the bundled highscore board was regenerated
- Changed: saved replays take about a third of the storage they used to, so your leaderboard is far less likely to hit the browser's storage limit and start dropping older runs. Same runs, same scores, just written more compactly — the bundled example board went from 424KB to 179KB over the wire
- Dev: the multiplayer level-transition check gates runs again instead of failing every one. It had been made advisory on the theory that the bot was unlucky, which was wrong — the failure repeated at identical coordinates across gameplay seeds. Six separate bugs, from a stuck route reporting no reason to a *completed* transition being read as a teleporter failure. The bot now fights its way to the exit when the level requires it, with combat enabled only for that fight
- Dev: bot failures are self-describing now — an anomaly names the errand it happened on, and a failure dumps the exit gate (where the bot was, which enemies belong to the exit's room, whether they're alive). Three of the six bugs above were invisible to the local harness built to reproduce them — it runs on a virtual clock, so it sees neither network delay nor the transition — and the dump found two in a single run after blind attempts had found none
- Dev: multiplayer telemetry records the bot configuration it ran under. `meta.flags` never existed in the multiplayer report, so the guard that refuses to compare runs from different bot behaviour has silently reported "not comparable" for every multiplayer A/B ever run. **Stored multiplayer runs from before this change should not be diffed against runs after it**
- Dev: the playtest bot navigates properly. It sprints down straight stretches, keeps moving while it turns instead of stopping dead at every corner, backs away from mines instead of turning into them first, re-plans mid-detour and after a fight shoves it round a corner, stops treating a door it opened as a wall, and takes keys in the order they stand in front of it. Levels finish 8-22% faster from the turning change and 27-41% faster from sprinting; planned routes are 25% shorter campaign-wide, 24-37% on the key-heavy levels. **Every pacing number this bot reported before is inflated by the standing around**
- Dev: the playtest bot fights better. It dodges while still lining up its own shot rather than only once aimed (hit 12% less, fights 12% faster, 28% more health left), steps off a bolt's flight line and sprints while doing it (ranged damage per second of exposure -25.4/-18.5/-7.9% across the profiles), picks weapons on reach and ammo economy instead of a fixed list (time-to-kill down 34-42%), and clears the enemies that keep an exit inert

- Dev: the frame-time root cause was narrower than "outlines are slow": the expensive class on a GPU-accelerated canvas is geometry the rasteriser can't emit as axis-aligned quads. - Dev: a CI guard (`src/engine/renderCost.test.ts`) fails the build if a per-frame renderer issues `fill()`, `stroke()` or `strokeRect()` on the scene canvas. This regression class is invisible both in review and to the headless harness, so the guard forces the pre-rendered fast path first and was verified red against a reintroduced regression

- Dev: the wall-texture verifier no longer asserts palette stability from sampled pixels — the frame is grabbed with the world running, so a roaming enemy in shot moved the mean between two launches of a byte-identical level, scaling with engine speed rather than with anything about the palette.
